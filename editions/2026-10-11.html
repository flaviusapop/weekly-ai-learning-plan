  1. Claude Code's Next Era, Thariq Shihipar, Latent Space, about 1h 32m new. It covers Claude Mods, Projects/Tag, prompting as the real skill, and why harnesses age so fast.Summary: Thariq presents Claude Code as an evolving agent harness: questions elicit requirements, artifacts provide persistent database-backed interfaces, and Claude Tag and Projects support parallel or multiplayer work. He argues that the core skill is building a mental model of the model, surfacing unknowns, and investing in context and planning up front; Mods then extend both the execution loop and the UI, making permissions and security central concerns.

It shows what shared team agent sessions actually feel like.Summary: OpenAI describes agents helping small open-source teams build together through workflows that share context across projects and contributors. The session demonstrates cloud sessions and computer use; the available source page does not provide a transcript, so the summary stays at that level.
  3. Where Will Investors Find Alpha in the Age of AI?, Alistair Smallwood (Primer) on Invest with AI / FundamentEdge, about 1h 12m new. It covers research agents, evals as the core skill, and where human judgment still beats autonomy.Summary: Smallwood discusses research infrastructure that improves as models improve, using primary-data retrieval, industry-specific agent skills, and adversarial evaluation to scale mosaic-style research. AI outputs are treated as prompts for investigation rather than complete investment theses; human judgment remains important for management context, competitor checks, and regime changes.

1) AI agents and workflows (about 3.5h more)

  • Inside Steve Yegge's Software Factory, re:cinq, about 70m new. Lessons from running about 50 agents.Summary: Yegge describes removing roughly 40% of a 50-agent software factory after excessive gates caused paralysis, while warning that false beliefs can spread through agent-generated code and documentation. He recommends mechanical governors, quotas, pace gates, substantial quality effort, and narrowly scoped production agents measured by outcomes rather than tokens or pull requests.
  • SE Radio 740: Building Production AI Agents, Raju Dandigam, about 58m new. Tool boundaries, evals and observability treated like real software.Summary: Dandigam treats an agent as a controlled software subsystem: define decision contracts and tool boundaries, keep authentication, policy, data freshness, and idempotency in the runtime, and prefer simple workflows before multi-agent orchestration. The episode covers contract-based tests, golden scenarios, readable execution trees, and production metrics such as cost and latency per run.
  • How we built an agent harness that cuts token use about 90%, AJ Asver, about 20m read new. A measured cost drop from $2.89 to $0.25.Summary: Asver describes recording agent traces, turning repeatable steps into code, and using typed questions for narrow evidence and routing decisions while reserving general agents for unfamiliar cases. In a compliance-screening comparison, the workflow reduced one investigation from 826 tool calls and 51 minutes to roughly 30 calls and three minutes; the article cautions that agreement with an LLM judge is not ground truth.

2) Investing and trading with AI (about 2.3h more)

This was the thinnest topic once I filtered out vendor content.

  • Joseph Chen: AI-Powered Backtesting and Trading Systems, Blushing Quants #41, about 1h 15m new. It covers where AI helps and where it speeds up overfitting.Summary: The episode notes argue against asking an AI coding tool to build a trading system from scratch. AI should work inside a modular framework with trusted data, reusable libraries, explicit interfaces, and established backtesting procedures; data adjustments, timestamps, fills, costs, broker behavior, intermediate signals, and order events all need auditing. Repeated AI optimization can accelerate overfitting, so the notes recommend sensitivity analysis, protected validation, limited-capital deployment, and live-behavior checks.
  • Peter Kostovčík: Why Features Matter More Than Models, Blushing Quants #40, about 1h 3m new. Pick episode #40 on the feed.Summary: The episode listing emphasizes that meaningful features, data understanding, and a correct objective often matter more than model sophistication. It favors classification, ranking, probability distributions, and clustering over exact-return prediction for large equity universes, while stressing simple statistical tests, protected out-of-sample periods, liquidity, slippage, turnover, and portfolio constraints; the supplied homepage does not include a transcript.

3) Product and building with AI (about 2h)

  • How Warp ships 2,000 PRs a month with AI factories, Zach Lloyd on How I AI, about 45m new.Summary: Lloyd explains Warp’s software-factory workflow, which turns requests from Slack, Linear, or GitHub into tracked and tested pull requests rather than relying on a standalone coding agent. The system uses automated triggers, human interactions per PR, LLM-as-a-judge scoring, failure-mode analysis, and replayed tasks to build cost-quality comparisons between models; human review remains a bottleneck.
  • Built a $500K Business Solo With Claude Code, Mark Fershteyn on GTM AI, about 35m new.Summary: Fershteyn describes using Claude Code as a nontechnical solo builder after shutting down Recapped, reaching a stated roughly $500K run rate six months into working part-time. His workflow starts in plan mode, assigns focused tasks to agents, improves skills through examples and feedback, and chains agents for content ideation, drafting, editing, hooks, and repurposing; he also shows a GitHub-backed knowledge base and a Claude/Vercel/Supabase workspace.
  • How OpenAI uses ChatGPT Sites, Kath Korevec on How I AI, about 36m new.Summary: Korevec demonstrates ChatGPT Sites turning live Slack, Notion, and calendar data into personalized internal tools, including an incident command center that surfaces relevant incidents and runbooks. Other examples include a Reddit-to-Spotify workflow and a shared dungeon crawler extended through custom skills; the common pattern is fast, disposable software with connector-based personalization and human approval for messages sent in the user’s name.
  • Brian Chesky: AI agents need their own OS, TechCrunch, about 12m read new.Summary: Chesky argues that chatbots are poor interfaces for browsing and group travel planning because they offer limited options, require repeated turns, and are not collaborative. He wants richer and multiplayer interfaces, robust app infrastructure, and interoperability through standards such as MCP, with specialized Airbnb agents coordinated by a broader agent rather than a single “quarterback” layered onto existing operating systems.
