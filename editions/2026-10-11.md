## 1) AI agents and workflows (about 3.5h more)

- [Inside Steve Yegge's Software Factory](https://re-cinq.com/podcast/steve-yegge-software-factory), re:cinq, about 70m, new. Lessons from running about 50 agents.
  **Summary:** Yegge describes removing roughly 40% of a 50-agent software factory after excessive gates caused paralysis, while warning that false beliefs can spread through agent-generated code and documentation. He recommends mechanical governors, quotas, pace gates, substantial quality effort, and narrowly scoped production agents measured by outcomes rather than tokens or pull requests.
- [SE Radio 740: Building Production AI Agents](https://se-radio.net/2026/09/se-radio-740-raju-dandigam-on-building-production-ai-agents/), Raju Dandigam, about 58m, new. Tool boundaries, evals and observability treated like real software.
  **Summary:** Dandigam treats an agent as a controlled software subsystem: define decision contracts and tool boundaries, keep authentication, policy, data freshness, and idempotency in the runtime, and prefer simple workflows before multi-agent orchestration. The episode covers contract-based tests, golden scenarios, readable execution trees, and production metrics such as cost and latency per run.
- [How we built an agent harness that cuts token use about 90%](https://operatorsguidetoai.substack.com/p/how-we-built-an-agent-harness-that), AJ Asver, about 20m read, new. A measured cost drop from $2.89 to $0.25.
  **Summary:** Asver describes recording agent traces, turning repeatable steps into code, and using typed questions for narrow evidence and routing decisions while reserving general agents for unfamiliar cases. In a compliance-screening comparison, the workflow reduced one investigation from 826 tool calls and 51 minutes to roughly 30 calls and three minutes; the article cautions that agreement with an LLM judge is not ground truth.

## 2) Investing and trading with AI (about 2.3h more)

This was the thinnest topic once I filtered out vendor content.

- [Joseph Chen: AI-Powered Backtesting and Trading Systems](https://theblushingquants.podbean.com/e/joseph-chen-building-ai-powered-backtesting-and-trading-systems-blushing-quants-41/), Blushing Quants #41, about 1h 15m, new. It covers where AI helps and where it speeds up overfitting.
  **Summary:** The episode notes argue against asking an AI coding tool to build a trading system from scratch. AI should work inside a modular framework with trusted data, reusable libraries, explicit interfaces, and established backtesting procedures; data adjustments, timestamps, fills, costs, broker behavior, intermediate signals, and order events all need auditing. Repeated AI optimization can accelerate overfitting, so the notes recommend sensitivity analysis, protected validation, limited-capital deployment, and live-behavior checks.
- [Peter Kostovčík: Why Features Matter More Than Models](https://theblushingquants.podbean.com/), Blushing Quants #40, about 1h 3m, new. Pick episode #40 on the feed.
  **Summary:** The episode listing emphasizes that meaningful features, data understanding, and a correct objective often matter more than model sophistication. It favors classification, ranking, probability distributions, and clustering over exact-return prediction for large equity universes, while stressing simple statistical tests, protected out-of-sample periods, liquidity, slippage, turnover, and portfolio constraints; the supplied homepage does not include a transcript.

## 3) Product and building with AI (about 2h)

- [How Warp ships 2,000 PRs a month with AI factories](https://www.lennysnewsletter.com/p/how-warp-ships-2000-prs-a-month-with), Zach Lloyd on How I AI, about 45m, new.
  **Summary:** Lloyd explains Warp’s software-factory workflow, which turns requests from Slack, Linear, or GitHub into tracked and tested pull requests rather than relying on a standalone coding agent. The system uses automated triggers, human interactions per PR, LLM-as-a-judge scoring, failure-mode analysis, and replayed tasks to build cost-quality comparisons between models; human review remains a bottleneck.
- [Built a $500K Business Solo With Claude Code](https://www.gtmaipodcast.com/p/92326-built-a-500k-business-solo), Mark Fershteyn on GTM AI, about 35m, new.
  **Summary:** Fershteyn describes using Claude Code as a nontechnical solo builder after shutting down Recapped, reaching a stated roughly $500K run rate six months into working part-time. His workflow starts in plan mode, assigns focused tasks to agents, improves skills through examples and feedback, and chains agents for content ideation, drafting, editing, hooks, and repurposing; he also shows a GitHub-backed knowledge base and a Claude/Vercel/Supabase workspace.
- [How OpenAI uses ChatGPT Sites](https://www.lennysnewsletter.com/p/how-i-ai-8-real-jev-use-cases-how), Kath Korevec on How I AI, about 36m, new.
  **Summary:** Korevec demonstrates ChatGPT Sites turning live Slack, Notion, and calendar data into personalized internal tools, including an incident command center that surfaces relevant incidents and runbooks. Other examples include a Reddit-to-Spotify workflow and a shared dungeon crawler extended through custom skills; the common pattern is fast, disposable software with connector-based personalization and human approval for messages sent in the user’s name.
- [Brian Chesky: AI agents need their own OS](https://techcrunch.com/2026/10/01/brian-chesky-interview-ai-agents-need-their-own-operating-system/), TechCrunch, about 12m read, new.
  **Summary:** Chesky argues that chatbots are poor interfaces for browsing and group travel planning because they offer limited options, require repeated turns, and are not collaborative. He wants richer and multiplayer interfaces, robust app infrastructure, and interoperability through standards such as MCP, with specialized Airbnb agents coordinated by a broader agent rather than a single “quarterback” layered onto existing operating systems.
